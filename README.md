# Remote Access — Address Book

Адресная книга для запуска сессий удалённого доступа (AnyDesk, Rudesktop, Ассистент,
AmmyyAdmin, RDP). Аналог SiaBook.

Стек: C# / .NET 8, WPF (MVVM), SQLite (`Microsoft.Data.Sqlite`), ClosedXML для чтения XLSX.

## Сборка

Требуется .NET SDK 8.0.

```
dotnet build
```

Публикация в один self-contained exe:

```
dotnet publish RemoteAccessAddressBook.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Готовый файл: `bin\Release\net8.0-windows\win-x64\publish\RemoteAccessAddressBook.exe`.

## Где лежат данные

| Что | Путь по умолчанию |
| --- | --- |
| База данных | `addressbook.db` рядом с exe |
| Настройки | `settings.json` рядом с exe |

Путь к БД меняется в окне настроек. Если файла БД нет — он создаётся автоматически
вместе со схемой. Относительный путь трактуется относительно каталога с exe.

Схема БД: `contacts`, `groups`, `labels`, `contact_labels` (many-to-many), `settings`,
`db_revision` (счётчик изменений, см. ниже).

### Общая база в сети

С одной базой могут работать несколько человек: положите `addressbook.db` в общую
папку и укажите её в настройках каждого экземпляра — сетевым путём
(`\\server\share\addressbook.db`) или через подключённый диск. `settings.json` у каждого
свой.

Как это устроено:

- **Блокировки.** SQLite работает в режиме обычного журнала (`journal_mode=DELETE`) и
  полагается на блокировки файлов SMB. Режим WAL по сети не работает, поэтому при
  открытии база принудительно переводится в DELETE. Соединение открывается на одну
  операцию и сразу закрывается, а пока другой экземпляр пишет, запись ждёт до 30 с.
- **Изменения коллег.** Любая запись в контакты, группы и метки увеличивает счётчик
  `db_revision` — это делают триггеры в самой базе, поэтому они срабатывают и для
  старых версий программы. Каждые 5 секунд приложение в фоне сверяет счётчик и, если он
  изменился, перечитывает данные. Прокрутка таблицы и выделенная строка сохраняются.
  Перечитать сразу — кнопка «Обновить» в шапке или **F5**.
- **Одновременное редактирование.** У каждой строки контакта есть номер версии (колонка
  `version`; её увеличивает и триггер, так что правки из старых версий программы тоже
  учитываются). Контакт сохраняется, только если версия не изменилась с момента открытия
  окна. Иначе программа спросит, сохранить ваш
  вариант поверх или взять актуальные данные. Если контакт успели удалить —
  предложит сохранить ваш вариант как новый.
- **Обрыв сети.** Если база недоступна, в строке статуса появляется сообщение, а
  проверка повторяется сама; после восстановления связи данные подтянутся.

Ограничения: это файловая база, а не сервер. Она рассчитана на небольшую команду
(единицы–десятки человек) и редкие правки. Общую папку держите на надёжном файловом
сервере Windows или Samba с включёнными блокировками; облачные синхронизаторы
(OneDrive, Яндекс Диск и т. п.) для общей базы не подходят — они копируют файл
целиком и могут его повредить.

### Шифрование локальной базы

По умолчанию локальная база не зашифрована. Включается в меню облака в шапке окна:
**«Зашифровать локальную базу…»**.

- Шифруются поля контакта: имя, комментарий, ID, RDP, логины и пароли (AES-256-GCM, ключ
  из парольной фразы через PBKDF2-SHA256, 600 000 итераций). Названия групп и меток
  остаются открытыми.
- После включения файл базы переписывается целиком (`VACUUM`), а удалённые данные
  затираются (`secure_delete`), чтобы открытые значения не остались в свободных страницах.
- В базе хранятся только соль и проверочный блоб фразы. Ключ сохраняется на компьютере
  в `settings.json` под защитой DPAPI текущего пользователя Windows, поэтому фраза
  спрашивается один раз. На другом компьютере (или у другого пользователя) её нужно
  ввести заново.
- Если фразу не ввести, локальные контакты скрыты, облачные видны. **F5** — ввести снова.
- Версии программы до 1.1 зашифрованных значений не прочитают: они увидят строки
  `enc:v1:…`.
- Снять шифрование можно тем же пунктом меню.

## Облачная база

Кроме локальной/сетевой базы, приложение может работать с общей облачной базой на
своём сервере (VPS под Ubuntu или Windows). Как поднять сервер, описано в
[Server/README.md](Server/README.md).

**Подключение.** Кнопка облака в шапке → «Подключиться к облачной базе…». Нужно указать
адрес сервера, логин, пароль, затем парольную фразу команды. Первый вошедший
администратор фразу задаёт. Пароль не сохраняется: программа хранит только токен
доступа и ключ шифрования, оба под защитой DPAPI.

**Шифрование сквозное.** Каждый контакт шифруется в приложении до отправки
(AES-256-GCM, ключ из фразы). Сервер хранит только шифротекст и прочитать контакты
не может. Кэш облачных записей на диске (`%LOCALAPPDATA%\RemoteAccessAddressBook`)
тоже зашифрован, поэтому без связи с сервером контакты видны, а изменить их нельзя.

**Как показываются две базы.**

- Сначала облачные контакты (значок облака), затем локальные (значок файла).
- **Дубль** — локальный контакт, у которого все поля (имя, комментарий, ID, логины, пароли)
  совпадают с облачным. Он не показывается, даже если у него другая группа или метки:
  приоритет у облачной версии. Поэтому переименование группы коллегой не превращает
  ваши локальные копии в расхождения.
- **Расхождение** — один и тот же контакт в обеих базах (совпал хотя бы один ID, а если
  ID нет — имя), но данные разные. Видны обе версии с красным значком. Правый клик →
  «Разобрать расхождение…» показывает их рядом, различия выделены. Можно оставить
  облачную (обновится локальная), локальную (обновится облако) или обе как есть.
- Группы и метки обеих баз объединяются по имени (без учёта регистра).

**Новый контакт.** В окне есть галочка **«Сохранить в облачную базу»**. Её последнее
состояние запоминается. Если облако недоступно, галочка неактивна и контакт
сохраняется в локальную базу.

**Синхронизация** (меню облака):

- «Скопировать облако → локальная база…» и «Скопировать локальная база → облако…».
  Новые контакты добавляются, дубли пропускаются (группа и метки при этом не
  сравниваются и не переносятся). При расхождении программа
  спрашивает: заменить, оставить как есть или сохранить оба. Есть галочка «применить
  ко всем».
- Удаления не переносятся: контакт, удалённый в одной базе, в другой останется.
- Один контакт можно скопировать в другую базу из контекстного меню строки.

**Совместная работа.** Изменения коллег в облаке подтягиваются каждые 5 секунд, как и
для сетевой базы. Сервер проверяет версию каждой записи. Если контакт изменили, пока он
был открыт у вас, программа спросит, сохранить ли ваш вариант поверх.

**Отключение.** «Отключиться от облачной базы» отзывает токен и удаляет кэш на этом
компьютере. На сервере контакты остаются.

## Интерфейс

- **Метки** — теги, у контакта их может быть несколько. Клик фильтрует таблицу,
  кнопка со «стёркой» в шапке панели сбрасывает фильтр.
- **Группы** — у контакта ровно одна группа (или «Без группы»). Пункты «Все» и
  «Без группы» служебные: их нельзя переименовать или удалить.
- Фильтры по метке и по группе независимы и комбинируются по «И», поверх них
  применяется текстовый поиск. Если панель отключена в настройках — её фильтр не
  применяется, а панель скрыта.
- **Тема** — светлая или тёмная. Переключается кнопкой (солнце/луна) в шапке окна
  или в настройках, где есть третий вариант «Как в системе» (читается настройка
  Windows «Режим приложения по умолчанию»). Тема применяется сразу, без перезапуска,
  и сохраняется в `settings.json` (`"Theme": "System" | "Light" | "Dark"`).
  Системные диалоги (сообщения, выбор файла) рисует Windows — они остаются в
  оформлении системы.
- **Ширина колонок** меняется перетаскиванием границы в шапке таблицы и запоминается
  между запусками (в `settings.json`, секция `ColumnWidths`). Колонки «Пароль» и
  «RDP Пароль» существуют парами (маска и открытый текст) и имеют общую ширину.
- **Порядок колонок** меняется перетаскиванием заголовка и тоже запоминается
  (секция `ColumnOrder`). Колонки пары переезжают вместе.
- **Панель иконок** над таблицей показывает программы удалённого доступа: яркая
  иконка — программа найдена на компьютере (в подсказке полный путь), бледная
  заглушка с буквой — не найдена, путь нужно указать в настройках. Иконка берётся
  из самого exe; список обновляется при запуске и после сохранения настроек.
  **Клик по иконке запускает программу** (без подключения к контакту); если путь не
  найден, показывается сообщение с подсказкой, где его задать.
- «Показать пароли» переключает колонки «Пароль» / «RDP Пароль» между маской и
  значением.
- Двойной клик по ячейке AnyDesk / Rudesktop / Ассистент / AmmyyAdmin / RDP запускает
  подключение; по остальным колонкам — открывает окно редактирования контакта.
  Для Ассистента и RuDesktop двойной клик копирует ID в буфер обмена и запускает
  программу (см. «Настройка команд подключения»).
- **Контекстное меню строки** (правый клик или клавиша меню): «Подключиться» —
  подменю со всеми программами, активны только те, для которых у контакта задан ID;
  программа колонки, по которой кликнули, выделена жирным. Далее «Изменить» и «Удалить».
- **О приложении** — кнопка «i» в шапке окна: версия, пути к базе и `settings.json`
  (с кнопкой «Открыть папку»), версия .NET и Windows.
- Размер и положение окна, выбранная группа и состояние переключателей панелей
  сохраняются между запусками.

## Настройка команд подключения

Для каждого инструмента в настройках задаются:

- путь к исполняемому файлу;
- шаблон аргументов с плейсхолдерами `{id}`, `{password}`, `{login}`;
- «Передавать пароль в stdin» — для AnyDesk с `--with-password`;
- «Сохранять учётные данные через cmdkey» — для RDP;
- «Копировать ID в буфер и просто запустить» — для программ, которые не умеют
  подключаться по параметрам командной строки (Ассистент, RuDesktop). В этом режиме
  ID не передаётся в аргументах: он копируется в буфер обмена, программа запускается
  без параметров, и ID остаётся вставить в её поле подключения. Результат
  показывается строкой рядом с заголовком группы.

Значения по умолчанию (**проверьте/уточните синтаксис под вашу версию программы**):

| Инструмент | exe | Аргументы | Примечание |
| --- | --- | --- | --- |
| AnyDesk | `anydesk.exe` | `{id} --with-password` | пароль передаётся в stdin |
| Rudesktop | — | — | режим «копировать ID и запустить» |
| Ассистент | `C:\Program Files (x86)\Ассистент\assistant.exe` | — | режим «копировать ID и запустить» |
| AmmyyAdmin | `AA_v3.exe` | `-connect {id}` | |
| RDP | `mstsc.exe` | `/v:{id}` | перед запуском выполняется `cmdkey /generic:TERMSRV/{id} /user:{login} /pass:{password}` |

Если exe не найден, показывается сообщение с путём, который не удалось запустить.

### Ассистент: параметры командной строки

Из руководства «Ассистент. Клиентское приложение», версия 6.5, раздел 15
([PDF](https://мойассистент.рф/assets/doc/site/User%20Manual.%20Client%20application.pdf)).

Windows: `-CONNECT:` (подключиться к устройству), `-USE_PASSWORD:` (безопасная передача
пароля в `-CONNECT`), `-IDSRV:` (свой ID-сервер), `-ACFG:` (импорт настроек из файла),
`-TOKEN_FILE:`, `-DEBUG`, `-NOUPDATE`. Пример из документации:

```
"C:\Program Files (x86)\Ассистент\assistant.exe" -CONNECT: 216042396
```

Linux (`/opt/assistant/bin/assistant`) — те же параметры плюс `-p` / `--password=<пароль>`,
`-e` / `--erase-password`, `-break`, `-x` / `--proxy-password=`, `-r` / `--erase-proxy-password`.

**На практике подключение по `-CONNECT:` не работает**, поэтому по умолчанию для
Ассистента (как и для RuDesktop) включён режим «копировать ID в буфер и просто
запустить». Параметры выше оставлены как справка: если в вашей версии `-CONNECT:`
всё же сработает, снимите галочку режима и впишите `-CONNECT: {id}` в поле аргументов.

Настройки, созданные более ранней версией приложения, мигрируют автоматически:
шаблон с `-CONNECT:` очищается и включается режим копирования ID.

### Автопоиск установленных программ

Кнопка **«Найти установленные»** в настройках ищет программы в системе и подставляет
пути. Тот же поиск выполняется автоматически при первом запуске (когда `settings.json`
ещё нет), поэтому обычно ничего настраивать не нужно.

Где ищем, по порядку:

1. `App Paths` в реестре (`HKLM`/`HKCU`, включая ветку `WOW6432Node`);
2. список установленных программ (`...\Uninstall`) — по названию, затем
   `InstallLocation` и `DisplayIcon`;
3. стандартные каталоги: `Program Files`, `Program Files (x86)`, `LocalAppData`
   (и `LocalAppData\Programs`), `AppData`, `ProgramData`, `System32`, рабочий стол,
   `Downloads` и каталог самой программы — с заходом на 1–2 уровня в подкаталоги
   вроде `AnyDesk`, `RuDesktop`, `Ассистент`, `Ammyy` (полный обход дисков не делается);
4. каталоги из переменной `PATH`.

Ищутся файлы `AnyDesk.exe`, `RuDesktop.exe`, `assistant.exe`, `AA_v3.exe` /
`Ammyy_Admin.exe`, `mstsc.exe` — список в `Services/ToolDiscoveryService.cs`, туда же
добавляются имена для нестандартных сборок.

Автопоиск заполняет только пустые или нерабочие пути (заданные вручную не трогает);
если все пути уже рабочие, кнопка спросит, перезаписать ли их найденными. Шаблоны
аргументов автопоиск не меняет.

## Импорт

Кнопка «Импорт CSV/XLSX» (в шапке окна и на панели фильтров). В окне импорта:
выбирается файл, группа назначения и соответствие «поле контакта → колонка файла»
(разделитель CSV определяется автоматически; заголовки сопоставляются с полями
эвристически, маппинг можно поправить вручную).

Перед добавлением каждая строка сравнивается с уже существующими контактами по **всем
сопоставленным полям, кроме паролей**; совпавшие строки считаются дубликатами и
не добавляются. По завершении показывается отчёт: добавлено / пропущено как дубликаты /
ошибок.

Импорт идёт в локальную базу. Перенести импортированное в облако можно синхронизацией.
